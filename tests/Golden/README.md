# Эталонные тесты (Golden)

Каждый эталон — папка `tests/Golden/<источник>-<номер>/`:

```
input.waproj    # сеть и исходные данные
expected.json   # ожидаемые величины с допусками
source.md       # источник, страницы, допущения при переносе, как проверено
```

| Эталон | Что проверяет | Статус |
|---|---|---|
| `GidRaVPT-R2` | совместимость с ГидРаВПТ 2.9.6: секция с кольцевыми питающими и двумя ПК, P секции, давление насоса | `pending` — множитель 1/0,95² не объяснён (open_questions.md, В-05) |
| `GidRaVPT-R2-plain` | та же секция, расчёт ГидРаВПТ без множителя (из файла проекта `.hvd`) | `compat` |
| `Meshman2002-P9-v1`, `-v2` | тупиковая сеть: 2 рядка по 7 оросителей, метод характеристик, потери через A | `active` |
| `Volkov2020-Ex1` | тупиковая сеть: 2 рядка по 4 оросителя, Kт по табл. Б.2 | `active` |
| `IOS2.2` | реальный проект; будет `compat`: сверяется то, что в проекте посчитано, ошибки проекта помечаются как ошибки источника (open_questions.md, В-10) | — |

Эталоны из старых норм (НПБ 88-2001, СП 5.13130.2009) проверяют гидравлику, а не нормативные параметры.

## Формат (предварительный, до JSON-схемы этапа 1)

`input.waproj` следует README §6.3 и дополняет его:

- `network.nodes[]`: `id`, `type` (`sprinkler`, `tee`, `hydrant`, `source`), `z` (м), для оросителя — `sprinkler` (id каталога) и `K` (л/(с·МПа^0,5)); у пожарного крана — `K`, `qNorm`, `pNorm`. Координат x, y в эталонах из книг нет.
- **Какой K берётся:** `K` узла важнее записи в `sprinklers[]` проекта, а она важнее каталога (`data/catalog`). В эталонах Мешмана у крайних оросителей рядков `K` задан намеренно (0,379473 вместо 0,35 по каталогу) — см. `transferNotes`; если взять K из каталога, эти эталоны разойдутся.
- `network.pipes[]`: `id`, `from`, `to` — **`from` всегда ближе к источнику** (по направлению потока при пожаре); `length` (м), `dn`; для стальных труб — `standard`, `od`, `wall` (мм): Kт берётся из табл. Б.2, а если строки нет — по формуле Б.8 по внутреннему диаметру. Вместо этого может быть задано `A` (с²/л², потери A·Q²·L/100) — так считают книжные примеры. `ring: true` — признак «кольцевого» участка ГидРаВПТ, `kind: "hydrant"` — труба к ПК.
- Узел `type: "source"` — точка, где задано давление (узел управления или точка, где книга обрывает расчёт). `dictating` — диктующий ороситель и его давление P, МПа (проектный режим, README §5.4).
- `settings.localLossFactor` — доля местных потерь, добавляемая к каждой трубе (0 во всех эталонах: книги считают без неё, а ГидРаВПТ добавляет 20 % по своему правилу из `compat`).
- `compat` — правила стороннего расчёта, которые надо включить, чтобы совпасть с источником (README §5, ARCHITECTURE §9.2). Только для тестов, в записку не идут. Поля:
  - `ringHalfFlow` — труба с `ring: true` считается на Q/2 (потери ×1/4);
  - `pipeFlowDivisor`, `pipeFlowDivisorExemptKinds` — трубы, кроме указанных видов (`kind`), считаются на Q/делитель (потери ×1/делитель²);
  - `pathLocalLossFactor` — P секции = P источника + P_уу + доля·Σ потерь труб диктующего пути;
  - `supplyLocalLossFactor` — к давлению после подводящих добавляется доля·Σ их потерь;
  - `notes` — пояснения.
- `controlValve` — `xi`, `gamma`, `flowUnit` (`m3/h` или `l/s`), `resultUnit`: P_уу = ξ·γ·Q² (Б.32 в прочтении источника).
- `pump` — `axisZ` (отметка оси, м), `inletPressure` (подпор, МПа), `supplyPipes` (подводящие трубы, по порядку от узла управления к насосу). Давление насоса = давление с местными потерями подводящих + (z источника − z оси)/100 − подпор.
- `transferNotes` — допущения при переносе.

`expected.json` следует README §6.4 и дополняет его: `status` (`active` — тест обязан проходить; `compat` — проходит в режиме совместимости; `pending` — не блокирует CI), `statusReason`, `tolerancePolicy`; у проверки — `source` (страница). Виды проверок `what`: `q` (расход оросителя или ПК), `P` (давление в узле), `dP` (потери на трубе), `Q` (расход по трубе), `v` (скорость воды в трубе, м/с, только для труб с сортаментом — `standard`/`od`/`wall`; v = Q/(π·d²/4), d — внутренний диаметр), `Kt`, `Qc` (расход установки), `Puu` (потери в УУ), `Psection`, `Psupply`, `PwithLocal`, `Ppump`.

## Как проверены эталоны

Эталоны со статусом `active` и `compat` прогоняются в CI тестом `tests/WaterAuto.Calc.Tests/GoldenTests.cs` через `TreeSolver` (ADR 0002); `pending` — только проверка, что сеть читается и считается без ошибок.

Кроме того, при оформлении входные файлы пересчитаны независимым решателем (метод глобального градиента, подбор давления источника под давление диктующего) вне репозитория: по `input.waproj` воспроизведены все величины `expected.json` в пределах допусков. Скрипт в репозиторий не входит. Так оба расчёта — независимый и `TreeSolver` — сходятся на одних и тех же файлах.
