# Water_Auto — правила для агента

Программа расчёта водяных АУПТ по СП 485.1311500.2020. Перед работой прочитай `README.md` и `docs/ARCHITECTURE.md`.

## Сборка и проверка

```bash
dotnet build WaterAuto.sln -c Release
dotnet test WaterAuto.Core.slnf -c Release
dotnet run --project tools/ValidateData -- data/
```

Сборка без предупреждений. SDK — .NET 10 (`global.json`), библиотеки — `net8.0`, приложение — `net8.0-windows` (ADR 0001).

## Жёсткие правила

- **Нормы — только данные.** Ни одного нормативного числа в C#. Значения берутся из `data/norms`, у каждого есть документ, пункт и редакция. Источник чисел — только действующий СП 485 с изменениями.
- **Не трактуй норму сам.** Если значения нет в данных или пункт допускает разные трактовки — остановись и заведи задачу «Вопрос по норме» (метка `question`).
- **Зависимости только к ядру.** Calc ссылается только на Core; Calc не знает про файлы, UI, время и случайность. Таблица разрешённых ссылок — `tests/WaterAuto.Architecture.Tests`. Новый проект — сначала правило там и в `ARCHITECTURE.md`.
- **Единицы ядра:** МПа, л/с, м (геометрия — мм). Физические величины в публичных API — типы-значения, не голые `double`.
- **Ошибки расчёта и нарушения норм — объекты `Issue`**, не исключения.
- **Сначала тест, потом код** для формул и этапов Calc.
- **Каждый JSON в `data/`** объявляет схему в поле `"$schema"` и проходит `ValidateData`.
- Новая зависимость — через ADR в `docs/adr/`. Только MIT, Apache, BSD, Boost и подобные; GPL-код не копировать.

## Работа с репозиторием

- Одна задача — одна ветка (`feat/`, `fix/`, `norms/`, `docs/`) и один небольшой PR. В `main` не мёржить.
- Коммиты — Conventional Commits: `feat(calc): …`, `norms(sp485): …`.
- Документацию заказчиков (чертежи объектов) в репозиторий не класть, только обезличенные эталоны. Тексты книг не копировать — выписки своими словами, числа и ссылки на страницы.
