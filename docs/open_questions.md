## В-01. Форма диктующей площади и правила её сдвига — [#8](https://github.com/Isaeev312/Water_Auto/issues/8)
- **Что в источниках.**
  - СП: площадь выделяют на плане, она равна минимальной площади по группе помещений (Б.1.1.8, Б.1.2.1). Число оросителей — «с учётом конфигурации» (Б.1.1.9). Форма и сдвиг не заданы.
  - М02: «самая удалённая или высокорасположенная» зона у дальней стены; в примере — прямоугольник во всю ширину зала (p99L, p170R).
  - СТУ СОБР (прил. Е): прямоугольник 3 × 4 оросителя в дальнем углу.
  - ГРВ: площадь задаёт проектировщик.
  - ИОС2.2: «наиболее удалённая», отдельно считается рампа, насос подбирается по худшему случаю.
- **Варианты.**
  - (а) Перебор прямоугольников площадью ≥ S с заданным соотношением сторон по всей сетке оросителей (ARCHITECTURE §7.3).
  - (б) Только «самая удалённая» зона по длине пути от УУ.
  - (в) Задаёт пользователь, программа проверяет.
- **Кто решает:** специалист по АУПТ. Соотношение сторон по умолчанию — тоже он.
- **Сейчас в расчёте (ADR 0008):** N = ⌈S/(l·b)⌉ оросителей, ближайших к диктующему; диктующий выбирается перебором концов ветвей по наибольшему давлению насоса (строже «только самой удалённой»). Форма зоны (круг/прямоугольник) остаётся открытой; записка называет это прочтение.

## В-02. 20 % местных потерь: от каких труб — [#9](https://github.com/Isaeev312/Water_Auto/issues/9)
- **Что в источниках.**
  - СП, Б.1.3.13: 20 % «линейного сопротивления трубопроводов», включая узел управления.
  - СП, пояснение к Б.30: 20 % «от линейных потерь по длине подводящего и питающего трубопровода (от расчётного участка до насосной установки)». При этом P_уу в Б.30 — отдельное слагаемое. Обе фразы есть и в редакции 2020 г. — **противоречие внутри СП**.
  - ГРВ R2: 20 % дважды — от потерь труб диктующего пути (ветвь + питающие, без УУ) и от подводящих.
  - ИОС2.2: коэффициент 1,2 ко всем линейным потерям от диктующего оросителя до насосной.
  - ПП: 20 % только от магистрали (P_г + P_в).
  - М02 и С11: 20 % «в приближённых расчётах» от сопротивления сети; в примере М02 местных потерь нет.
  - СНиП II-Г.1-70 (исторически): 10–30 % по виду водопровода.
- **Варианты.**
  - (а) Все трубы сети, без УУ (P_уу по Б.32 отдельно).
  - (б) Все трубы, и 20 % заменяют P_уу (буквально Б.1.3.13).
  - (в) Только подводящие и питающие (пояснение к Б.30).
  - (г) Как ГРВ.
- **Влияние:** на напор насоса. В примере М02 (вариант 2) переход от 0 к 20 % на всей сети поднимает Pb с 0,312 до 0,361 МПа.
- **Кто решает:** специалист; возможно — письменный запрос во ВНИИПО. Сейчас README §5.1 и ARCHITECTURE §7.1 принимают вариант (а) с k_м = 0,2 на каждой трубе — это нужно подтвердить.
- **Сейчас в расчёте (ADR 0008):** 20 % на всех участках от диктующего оросителя до насоса, включая узел управления (Б.1.3.13 буквально) — строже пояснения к Б.30.

## В-03. Формула Б.32: единицы и γ — [#10](https://github.com/Isaeev312/Water_Auto/issues/10)
- **Что в источниках.**
  - СП (формула — изображение в docx с изм.): P_уу = ξ_уу·γ·Q² = (ξ_кс + ξ_з)·γ·Q². В пояснении γ названа «плотностью воды, кг/м³», Q — «м³/ч». Единица P_уу в заголовке Б.1.3.12 — «м», в пояснении к Б.30 — «МПа». Числа γ нет.
  - ГРВ: γ = 9,80665, Q в м³/ч, результат в МПа; ξ порядка 10⁻⁷–10⁻⁸. Это подтверждено пересчётом R2.
  - С11 (прил. В СП 5): то же, с теми же несостыковками.
  - М02 и С03: P = γQ² (e·Q²), Q в л/с, результат в м.
  - ИОС2.2: Ε·Q², Ε = 0,0022, Q в л/с, результат в м.
  - ПП: 0,01·ξ·Q² в МПа.
- **Варианты.**
  - (а) Как ГРВ (ARCHITECTURE §9.2).
  - (б) Ввод потерь по паспорту узла «как есть» с выбором единиц.
- **Кто решает:** специалист; сверить с паспортами УУ (Спецавтоматика, Tyco) — в каких единицах там дан ξ.
- **Сейчас в расчёте (ADR 0008):** без паспорта узла управления его потери входят в 20 % по Б.1.3.13; Б.32 не применяется, пока нет паспортных ξ.

## В-05. Множитель 1/0,95² в ГидРаВПТ 2.9.6 — [#12](https://github.com/Isaeev312/Water_Auto/issues/12)
- **Что видно.** В R2 потери всех труб сети, кроме труб ПК, больше Q²L/(100·Kт) ровно в 1/0,95² = 1,10803 раза; скорости больше в 1/0,95 раза. Численно трубы считаются на расход Q/0,95. В файле проекта `.hvd` та же секция посчитана без множителя, а PDF назван «после обновления» — значит, множитель появился с обновлением программы. Смысл (запас по расходу? иное?) в отчёте не объяснён.
- **Варианты.**
  - (а) Узнать у разработчика или в руководстве пользователя (112 с.). Вопрос можно задать в группе пользователей «ГидРаВПТ и Ко» в Telegram (t.me/gidravpt).
  - (б) Оставить эталон R2 в статусе `pending`, а совместимость проверять по `GidRaVPT-R2-plain`.
- **Кто решает:** владелец проекта (связь с разработчиком ГидРаВПТ).

## В-07. Жокей-насос: расход и уставки — [#14](https://github.com/Isaeev312/Water_Auto/issues/14)

## В-10. Эталон ИОС2.2 — внутренние расхождения в проекте — [#17](https://github.com/Isaeev312/Water_Auto/issues/17)
README делает зелёный `Golden/IOS2.2` условием мёржа изменений в Calc. При этом в проекте:
- расчёт по **СП 5.13130.2009**, а Kт — из табл. Б.2 СП 485;
- потери «кольцо – насосная» (DN150, 220 м, 36,5 л/с): в проекте 0,100 МПа, пересчёт даёт 0,068. От этого числа зависит напор ≈ 50 м;
- участки 4–5 и 5–6 посчитаны с Kт = 5205 (DN100), а на схеме это стояк Ø150;
- расчёт рампы не учитывает рост расхода рядков с давлением (35,20 л/с вместо ≈ 36,7);
- Z = 5,50 м при насосной на −5,800; отметка оросителя не указана;
- P диктующего = 0,175 МПа взято по графику TY365 (формула записана без множителя 10);
- уставки жокея и насосов даны дважды и не совпадают;
- Q насоса = 36,50 + 10,40 (ПК прибавлены по норме), H = 50 − 19 = 31 м; принятая точка 184,80 м³/ч / 34,90 м (p30, p41).
- **Варианты.**
  - (а) Эталон проверяет только то, что проект реально посчитал (распределительная сеть автостоянки с допуском 0,01 МПа), а итоговые 0,100 и 50 м помечаются как ошибки источника.
  - (б) Перенести роль эталона-гейта на `Volkov2020-Ex1` + `Meshman2002-P9-v2` + `GidRaVPT-R2-plain`, а ИОС2.2 сделать `compat`.
- **Решение владельца (PR #22, 25.10.2026):** «возможно, проект ИОС был выполнен с ошибкой — учитывай и этот момент». Принято (б) с элементами (а):
  - гейт мёржа Calc — `Volkov2020-Ex1`, `Meshman2002-P9-v1/-v2`, `GidRaVPT-R2-plain`;
  - ИОС2.2 — `compat`: сверяется только то, что в проекте действительно посчитано; расхождения из списка выше — ошибки источника, программа их не повторяет.

## А-17. Коэффициенты расчёта модулей порошкового пожаротушения без данных изготовителя
- **Суть:** прил. И СП 485 (формулы И.1, И.3) требует k1 (1…1,2), k2 (затенения), k3 (вещество) и k4. Числа k2 в своде нет ни для одного способа — его определяет изготовитель по огневым испытаниям; k1 внутри диапазона — без правила выбора; k3 для вещества вне табл. И.1 — экспериментально. k4 по площади (1,2) и локально (1,3) — в своде есть (символы сверены по изображениям).
- **Как делает программа:** k2 — только из паспорта модуля, без него расчёт не выполняется; k1, k4 — из паспорта, если он их даёт, иначе нормативные значения (k4 = 1,2 по площади, 1,3 локально, 1 + 10·f по объёму; k1 = 1,2 на максимальной высоте). Где числа нет ни в паспорте, ни в своде — ошибка с указанием, чего не хватает.
- **Решить:** k1 при высоте ниже максимальной (1,0 или 1,2 в запас) — решение проектировщика; k2 по объёму — только из паспорта.
