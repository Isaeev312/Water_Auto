# ADR 0001. Стек и сборка

Статус: принято · 25.10.2026 · этап 0

## Контекст

Ядро должно подключаться к плагинам AutoCAD 2025+ и Revit 2025+, которые работают на .NET 8. На машине разработки установлен только .NET SDK 10 (среды выполнения 8, 9 и 10 есть). Шаблоны `dotnet new` из SDK 10 не создают проекты под `net8.0`.

## Решение

- **SDK:** `global.json` фиксирует 10.0.100 с `rollForward: latestFeature`. SDK 10 собирает проекты под `net8.0`.
- **Целевые платформы:** библиотеки, CLI, тесты и `tools/` — `net8.0`; приложение — `net8.0-windows` (WPF). В CI ставится и SDK из `global.json`, и среда выполнения 8.0 для тестов.
- **Решение:** `WaterAuto.sln` в классическом формате (не `.slnx`), фильтр `WaterAuto.Core.slnf` без WPF — для сборки на Linux.
- **Версии пакетов** — централизованно в `Directory.Packages.props`.
- **Тесты:** xUnit 2, Shouldly. Тест архитектуры проверяет ссылки между проектами по `.csproj`: ссылки сборок на пустом скелете ничего не ловят, компилятор выбрасывает ссылку на сборку, из которой не используется ни один тип. NetArchTest подключим, когда появятся типы и правила на уровне кода (время, статическое состояние).
- **Проверка данных:** `tools/ValidateData` на JsonSchema.Net. Каждый JSON в `data/` объявляет свою схему полем `"$schema"` (путь относительно файла) — тогда и редактор подсказывает по схеме.

## Последствия

- README требовал «.NET SDK 8 или новее»; теперь нужен SDK 10. Целевые платформы не изменились, совместимость с плагинами сохраняется.
- `LangVersion latest` = C# 14: в коде, который пойдёт в плагины, это не мешает — язык не зависит от среды выполнения, кроме отдельных возможностей. При их использовании следить за предупреждениями компилятора.
