# ADR 0004. Раскладка оросителей: зоны, общие линии, перебор по сетке 10 мм

Статус: принято · 25.10.2026 · этап 2b

## Контекст

После импорта (ADR 0003) план надо покрыть спринклерными оросителями по табл. 6.1 и п. 6.2.21. Норма задаёт три числа:
- наибольший шаг (табл. 6.1, профиль заказчика может только уменьшить);
- наименьший шаг 1,5 м;
- **предел** расстояния до стены: ½ шага табл. 6.1 для К0/К1, 1,2 м для прочих.

Предел — это наибольшее расстояние, а не отступ. Прежняя формулировка ARCHITECTURE §6 («контур − отступ до стен») ставила бы крайние оросители на сам предел или дальше; исправлена.

## Решение

- **Правила — данные.** Значения 6.2.10, 6.2.14, 6.2.21 — в `data/norms/sp485/clauses_6_2.json`; `LayoutRules.Resolve` собирает их по группе помещений и классу конструкций (К0…К3, ненормируемый). Шаг строже табл. 6.1 принимается, шаг слабее — ошибка `layout.spacingLooser`.
- **К0/К1: предел — половина фактического шага.** При табличном шаге это и есть буквальное «половина шага табл. 6.1». При уменьшенном шаге (профиль Фонда реновации, 3,0 м) — строже буквального прочтения, поэтому норма соблюдается при любом прочтении (В-16).
- **Система координат помещения** — вдоль самой длинной стены. Стены, отличающиеся от параллельных и перпендикулярных больше 1 мм, — ошибка `layout.nonOrthogonal`: такие помещения пока не раскладываются.
- **Зоны.** Помещение делится разрезами по всем вершинам на прямоугольники; соседние полосы с одинаковым интервалом сливаются. Зоны запрета (ПТ_ЗАПРЕТ) — вырезы, их стороны считаются стенами (В-18). Считаются оба направления разрезов, берётся вариант с меньшим числом оросителей. Это и есть сравнение «X × Y и Y × X» из README §11: при одинаковом шаге по обеим осям прямоугольник от поворота сетки не меняется, а разрезы меняют.
- **Общие линии поперёк разрезов.** Линии одной оси общие для всего помещения, поэтому ряды соседних зон лежат на одной прямой и шаг через разрез измеряется вдоль ряда. Линии другой оси у каждой зоны свои. У разреза линия не дальше полшага (через разрез не больше шага) и не ближе половины наименьшего шага (через разрез не меньше 1,5 м).
- **Узкие зоны** (ниша, пилястра, ступенька стены в несколько миллиметров). Зона, в которой не помещается ни одна линия, своих оросителей не получает. Её дальнюю сторону обслуживают соседи, и их предел у общей стороны уменьшается:
  - дальняя сторона — стена: до неё не дальше предела 6.2.21 (предел − ширина зоны);
  - дальняя сторона — разрез: шаг через зону не больше нормы, поровну с соседом за ней ((шаг − ширина) / 2);
  - частично стена — меньшее из двух.

  Новых чисел нет: проверяется тот же 6.2.21 до дна ниши. Узкая щель между двумя стенами, которую никто не обслуживает, — `layout.sliver` (Warning) с координатами.
- **Подбор линий** — `LineSolver`, динамическое программирование по сетке 10 мм (координаты кратны 10 мм — удобно для чертежа). Цель:
  1. наименьшее число линий;
  2. при равном числе — наибольший из наименьших «шагов», где у конца отрезка шаг — удвоенное расстояние до него (у стены — полшага);
  3. затем — наименьшая сумма квадратов.

  Второй критерий нужен для Г-образных помещений: при одной только сумме квадратов линия вставала в 110 мм от внутренней стены.
- **Колонны.** Норма не задаёт расстояний до колонн, поэтому правил «тени» нет: ороситель только не должен попадать в колонну.
  - Сначала линии подбираются с обходом проекций колонн: общие линии, затем линии зоны. Обход принимается, если не добавляет линий.
  - Если ороситель всё же попал в колонну, он не ставится: замечание `layout.columnConflict` (Error) с координатами. Сдвиг одного оросителя не делается: подбор линий уже сдвигает целые линии везде, где это возможно без лишней линии, — там, где он не справился, сдвиг одного оросителя тоже нарушил бы шаг.
- **Балки** выше предела 6.2.10 — вырезы раскладки, как зоны без оросителей: перекрытие делится на поля, грани балки приняты как стены, до них не дальше предела 6.2.21 (строгое прочтение В-17; замечание `layout.beamFields` уровня Info называет его). Для трассы балки не препятствие: трубы проходят под ними.
- **Короба** шире предела 6.2.14 — `layout.duct` (Warning): высоты пола в плане нет, условие «не менее 0,7 м от пола» не проверяется.
- **Clipper2 пока не нужен.** Для прямоугольных контуров хватает своей геометрии. Clipper2 добавляется с отдельным ADR, когда понадобится вычитание полигонов (поля между балками, наклонные стены).

## Проверка

`LayoutChecks` в тестах не знает алгоритма. Из каждого оросителя по четырём направлениям сетки проверяется:
- до соседа на той же прямой — не больше шага;
- если соседа нет — до стены не больше предела;
- все пары — не ближе 1,5 м.

Отдельный тест убеждается, что проверка ловит пропущенный и сдвинутый ороситель.

## Последствия

- Наклонные стены, поля между балками, оросители под коробами — следующие шаги этапа 2.
- Трассировка рядков к `Inlet` — следующим PR.
- Раскладка требует от плана прямоугольных стен; на реальном чертеже (Маликова 91) проверить, сколько помещений это отсекает.
