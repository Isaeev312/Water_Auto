# ADR 0002. Гидравлика этапа 1: последовательный расчёт тупиковой сети

Статус: принято · 25.10.2026 · этап 1

## Контекст

README §5.6 требует, чтобы солвер на тупиковой сети совпадал с последовательным расчётом приложения Б (Б.9–Б.22) до 1·10⁻⁴ МПа. Значит, эталоном служит сам последовательный метод. Кольца и солвер глобального градиента (README §5.3) отнесены к этапу 4. Эталоны этапа 1 — `tests/Golden` (`Volkov2020-Ex1`, `Meshman2002-P9-v1/-v2`, `GidRaVPT-R2-plain`; `GidRaVPT-R2` отложен). `Golden/IOS2.2` пока не оформлен: в проекте есть расхождения (open_questions.md В-10, задача #17).

## Решение

- **`WaterAuto.Calc.Hydraulics.TreeSolver.SolveDesign`** — проектный режим: задано давление диктующего оросителя, ищется давление источника.
  - Путь от диктующего оросителя к источнику проходится по шагам: P(n+1) = P(n) + r·Q² с учётом отметок через пьезометрическое давление h = P + z/100.
  - Боковые ветви сворачиваются снизу вверх в характеристику C: ороситель — 10K, параллельно — сумма, последовательно с трубой — C' = 1/√(1/C² + r). В узле подключения Q = C·√(h − z_эм/100); это Б.17–Б.21, выравнивание ветвей.
  - Для дерева, у каждой боковой ветви которого эмиттеры на одной отметке, метод точен: итераций нет, погрешность — только округление double. Ветвь с эмиттерами на разных отметках даёт замечание `branch.mixedElevation`; такие сети считает солвер этапа 4.
  - Кольца (у узла больше одной входящей трубы) — замечание `topology.notTree`, а не исключение.
- **Труба** несёт Kт и множитель потерь: r = L/(100·Kт)·множитель. Kт определяет `PipeCharacteristics.Resolve`: строка табл. Б.2, иначе формула Б.8 с коэффициентами табл. Б.3 из `data/norms`. Удельное сопротивление A переводится в Kт = 1/A.
- **Calc не принимает спорных решений.** Доля местных потерь передаётся извне через множитель трубы: значение Б.1.3.13 лежит в `data/norms/sp485/appendix_B_clauses.json`, а к каким трубам его применять, решает вопрос В-02 (#9). Формулы Б.30 и Б.32 (узел управления, насос) в Calc этапа 1 не входят: единицы Б.32 спорны (В-03, #10). Правила сторонних программ (кольцо на Q/2, множитель 1/0,95², «20 % по ГидРаВПТ») применяются только в тестовом стенде `GoldenTests` по блоку `compat` эталона.
- **Нормы** читает `WaterAuto.Norms.JsonNormsProvider` через интерфейс `INormsProvider` из Core. Calc ссылается только на Core.

## Последствия

- Этап 4 добавляет солвер глобального градиента для колец и смешанных отметок. На тупиковых сетях он обязан совпасть с `TreeSolver` (README §5.6).
- Условие README §10 «изменение Calc без зелёного `Golden/IOS2.2` не мёржится» на этом этапе выполнить нельзя: эталона ещё нет, и неясно, каким он должен быть (#17). До решения роль контрольных выполняют эталоны со статусом `active` и `compat`.
- CalcLog со ссылками на пункты норм пока не ведётся: появится вместе с запиской (этап 3).
