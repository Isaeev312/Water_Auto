# ADR 0008. Проектный расчёт: диктующая зона, диаметры по Б.5, насос по Б.30, запас воды

Статус: принято · 25.10.2026 · этап 3a

## Контекст

Владелец проекта попросил полностью заполнить разделы 5–7 пояснительной записки экзаменационного проекта: формулы, подстановки и ссылки на нормы, без заготовок. Часть пунктов приложения Б допускает разные прочтения (В-01, В-02, В-03, В-08). Ждать решения нельзя, и выдумывать числа тоже нельзя. Поэтому в расчёте принято **строгое** прочтение, а записка прямо его называет. Вопросы остаются открытыми и выносятся на согласование с руководителем.

## Решение

`DesignCalculation.Run` (Calc) по трассе этапа 2c, нормам и данным проекта (`DesignSettings`):

1. **Диктующий ороситель** — самый удалённый от точки подключения по трассе (Б.1.2.1).
2. **Расход и давление у диктующего оросителя** (Б.1): q = k·i·s, p = (q/10K)².
   - Коэффициент k берётся верхний, 1,5, из диапазона 1,3–1,5 (запись `sp485.b1_1_12.dictatingFlowFactor`). Это больше расход и напор; В-08.
3. **Диктующая зона:** N = ⌈S / (l·b)⌉ (Б.2, Б.3).
   - l и b — шаг сетки у диктующего оросителя.
   - Зона — N оросителей, ближайших к диктующему, при равенстве — более удалённые по трассе. Форма зоны — В-01.
4. **Сеть** — последовательный расчёт `TreeSolver` (Б.4, Б.6, Б.17–Б.23). Открыты только оросители зоны.
   - Местные сопротивления — 20 % на всех участках от диктующего оросителя до насоса, включая узел управления (Б.1.3.13 буквально). Это шире, чем пояснение к Б.30; В-02.
   - Отдельно Б.32 при отсутствии паспорта узла управления не считается: Б.1.3.13 включает узел управления в 20 %. В-03 остаётся открытым для случая, когда паспортные данные есть.
5. **Диаметры по Б.5:** d = 1000·√(4Q/(π·μ·V)).
   - μ = 0,90 — нижнее значение диапазона, что даёт больший диаметр.
   - V задаёт проектировщик (`DesignVelocity`, не более 10 м/с).
   - Берётся ближайшая большая труба сортамента; расчёт повторяется до установления диаметров. Выше по течению DN не меньше, чем за участком.
   - Итоговые DN — в `DesignResult.Route`, оттуда спецификация и DXF.
6. **Расход насоса:** Б.24–Б.26, Q_нас = max(Q_р, Q_н).
7. **Давление насоса** (Б.30): P_н = P_вв + 1,2·ΔP_подв + Z − P_вх, Z = H/100 (В-13: H/100 по СП).
   - ΔP_подв — подводящий трубопровод от насоса до точки подключения при Q_нас.
8. **Скорости** проверяются по п. 6.7.1.37 (до 10 м/с в напорных).
9. **Запас воды:** W = Q_нас·t·60/1000, t — по табл. 6.1; вместимость резервуара V = W/0,95 (п. 6.9.13).
   - Резервуар обязателен при давлении в сети меньше 0,05 МПа (п. 6.9.12).
10. **Насосная установка** — требования пп. 6.9.4, 6.9.5, 6.9.8, 6.10.3, 6.10.5, 6.10.9, 6.10.11, 6.10.17 переносятся в записку текстом.

Все числа — из данных: табл. 6.1, Б.1.1.10, Б.1.1.12, Б.1.2.6, Б.1.3.13, Б.2, пп. 6.7.1.37, 6.9.4, 6.9.12, 6.9.13.

## Записка

Разделы 5–7 и заключение собирает `ExplanatoryNoteComposer`.
- Каждая формула идёт с номером и пояснением «где …» и с подстановкой чисел.
- Абзац «*Принято:*» перечисляет принятые прочтения со ссылками на пункты.
- Таблица гидравлического расчёта использует расчётные точки 1, 2… / а, б… / ВВ, с давлением в конце каждого участка.
- Разметка docx: полужирный, курсив, индексы, переносы строк (`NoteDocx`).

## Последствия

- Если руководитель примет другое прочтение (например, k = 1,3 или 20 % только на подводящих), меняется одна запись данных или одна строка расчёта, и записка пересобирается.
- Кольцевые питающие (Б.1.2.16.1) и поиск худшей из нескольких зон (ARCHITECTURE §7.3) — этап 4.
- Подбор насоса по характеристике требует данных производителя: открытых данных нет, характеристики вводит пользователь со ссылкой на источник.
