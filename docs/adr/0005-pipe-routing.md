# ADR 0005. Трассировка: рядки вдоль рядов, один питающий, начальные DN по табл. Б.4

Статус: принято · 25.10.2026 · этап 2c

## Контекст

Раскладка (ADR 0004) даёт оросители. Для гидравлики (этап 3) нужна сеть-дерево от ввода: рядки, питающий и подводящий трубопроводы с длинами и начальными диаметрами. Б.1.1.7: трассировка «намечается»; Б.1.3.2 и табл. Б.4: диаметры рядков — ориентировочно по числу оросителей, затем уточняются расчётом.

## Решение

- **Рядки** — вдоль общих линий раскладки (`LayoutZone.RowAngleRad`): на стыке зон ряды продолжают друг друга. Ряд рвётся там, где шаг больше нормы или труба вышла бы из помещения или прошла через зону запрета.
- **Один питающий** поперёк рядов.
  - **Кандидаты:** середины между соседними вертикалями оросителей и места у концов рядов.
  - **Выбор кандидата, по порядку:**
    1. больше рядов;
    2. больше оросителей;
    3. ветви по обе стороны ровнее (центральная подача — секция А на рис. Б.2);
    4. ближе к вводу.
  - Питающий идёт только внутри помещения, вне зон запрета и колонн.
  - Ряды, до которых он не дошёл, — ошибка `routing.rowNotReached` с координатами. Второй питающий и кольцо — позже.
- **Подводящий** от ввода (ПТ_ВВОД внутри помещения) — один или два прямых участка до питающего.
  - Он не ложится на трубу ряда: врезка в питающий — между рядами или у крайнего.
  - Пересечение рядов вертикальным участком допускается (трубы на разных уровнях), но стоит дороже.
  - Нет ввода — `routing.noInlet`; не соединить — `routing.inletUnreachable`.
- **Трубы через колонны:** колонны питающий обходит. Ряд, проходящий через колонну, даёт предупреждение `routing.throughColumn` — обход оформляется на чертеже. Раскладка сама уводит ряды от колонн, если это не добавляет линий.
- **Начальный DN** — `DnTable`, табл. Б.4 из `data/norms/sp485/table_B_4.json`.
  - DN берётся по числу оросителей за участком.
  - Столбец выбирается по расчётному давлению: порог 0,5 МПа — тоже из данных.
  - Таблица — для рядков; для питающего и подводящего она применяется как первое приближение (В-19), окончательно диаметры подбирает гидравлический расчёт этапа 3.
- **Сеть для солвера** — `RouteNetwork.Build`.
  - Ввод — источник, оросители — эмиттеры с K, Kт — строка табл. Б.2 выбранного стандарта по DN.
  - DN 70 из табл. Б.4, которого нет в ГОСТ 3262 (65 и 90), заменяется ближайшим большим (80) с замечанием `network.dnSubstituted` (В-19).
  - Несколько труб одного DN (ГОСТ 10704) — предупреждение: трубу надо задать явно.
- **Модель** — `PipeRoute`, `RouteNode`, `RouteSegment` в Core. Это источник для DXF (ПТ_ТРУБЫ, ПТ_УЧАСТКИ), аксонометрии и спецификации.

## Проверка

`RouteChecks` в тестах проверяет трассу без знания алгоритма:
- дерево от ввода: в каждый узел входит ровно один участок, все узлы достижимы;
- `Fed` совпадает с подсчётом;
- участки идут вдоль осей и внутри помещения, не лежат друг на друге, не проходят через колонны и зоны запрета.

Трасса 30 × 20 м превращается в сеть и решается `TreeSolver` без ошибок.

## Последствия

- Отметки узлов пока одни на всю сеть; стояк и разные уровни — этап 3.
- Второй питающий, кольцевой питающий, ограничение числа оросителей на ветви (В-09) — следующими шагами.
