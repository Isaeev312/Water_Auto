# Water_Auto — архитектура (v0.1, 25.10.2026)

Документ для разработчика и агента, работающего с кодом. Методика расчёта — `water_auto_methodology_sp485.md`, границы v1 — `water_auto_concept.md`, состав выпуска — `water_auto_golden_set.md`.

## 1. Принципы
1. **Ядро детерминированное и без интерфейса.** Core и Calc не знают про UI, файлы, время и случайность. Одинаковый вход даёт одинаковый результат.
2. **Нормы — данные, а не код.** Ни одного нормативного числа в C#. Всё берётся из `data/norms`, у каждого значения есть документ, пункт и редакция.
3. **Сеть — главный объект.** Гидравлика принимает граф сети из любого источника: автораскладка, ручной ввод, импорт из CAD. Раскладка — один из источников, а не часть расчёта.
4. **Стабильные ID.** У каждого узла, участка и оросителя постоянный ID. Он переживает пересчёт и обмен с CAD (основа обратного пути AutoCAD → расчёт).
5. **Прослеживаемость.** Каждый этап пишет журнал допущений и решений со ссылкой на пункт нормы. Из журнала собирается записка.
6. **Вертикальный срез раньше ширины.** Сначала один объект (паркинг Маликова 91) проходит от DWG до записки и спецификации, потом добавляются кольца, приложение В, дренчеры.

## 2. Стек
- C#, .NET. Библиотеки ядра (Core, Calc, Norms, Catalog, Import, Export, Reports) — `net8.0`, чтобы их без изменений подключить в плагины AutoCAD и Revit (они на .NET 8).
- Приложение — WPF, `net8.0-windows` (можно поднять позже, ядро от этого не зависит).
- Тесты — xUnit.

## 5. Доменная модель (Core)
- `Project` — объект, этажи, выбранный снимок норм (`NormsSnapshot`: документ, редакция, хэш), режим РЧВ, настройки.
- `Floor` → `Room`: контур (полигон, мм), высота, класс пожарной опасности конструкций (К0…К3), группа помещений, для склада — вид и высота складирования.
- Препятствия: `Column`, `Beam` (высота), `Duct` (ширина, отметка низа), `NoSprinklerZone`.
- `Inlet` — точка подключения (стояк, узел управления).
- Сеть: `Node` (ID, x, y, z, тип: ороситель, тройник, стояк, узел управления, насос, источник), `Pipe` (ID, узлы, DN, стандарт трубы, длина, Kт, местные потери), `Section` (секция, ≤ 800 оросителей, 6.2.3).
- Оборудование: `Sprinkler` (K, температура, положение розетки, инерционность), `Pump` (точки Q–H), `Tank` (размеры, мёртвый слой).
- Единицы — типы-значения (`Pressure` в МПа, `Flow` в л/с, `Length` в м), не голые `double`. Перевод м вод. ст. ↔ МПа только через тип.
- `CalcLog` — записи `{этап, величина, значение, ссылка на норму, допущение или решение}`.

## 6. Конвейер расчёта (Calc)
Каждый этап — чистая функция: `(модель, нормы, каталог) → (новая модель, журнал, замечания)`.

1. **Параметры по нормам**: группа (прил. А), i, Q, S, t, шаг (табл. 6.1–6.3, пересчёт по высоте по примеч. 3 к 6.2). Группа 7 на воде → ошибка «вне v1».
2. **Раскладка** (ADR 0004): помещение — вдоль своих стен, деление на прямоугольные зоны; линии оросителей с шагом не больше нормы (табл. 6.1 или профиль) и не меньше 1,5 м; крайние — не дальше предела от стен (½ шага для К0/К1, 1,2 м для прочих, 6.2.21 — это предел, а не отступ); колонны обходятся сдвигом линий, зоны запрета — вырезы со стенами. Между балками высотой > 0,3 м (К0/К1) или > 0,2 м (прочие) — отдельные поля (6.2.10), грани балок — как стены (В-17); под коробами > 0,75 м — дополнительные оросители (6.2.14): пока замечание. Затем трассировка (ADR 0005): рядки вдоль рядов, один питающий поперёк, подводящий к `Inlet`; начальные DN по табл. Б.4.
3. **Граф сети** и начальные диаметры (ориентир — табл. Б.4).
4. **Гидравлика** (раздел 7).
5. **Диктующая зона** (раздел 7.3), при нехватке площади орошения — увеличение DN и повтор (Б.1.1.12).
6. **Насос**: P_н по Б.30, Q_с по Б.23–Б.26; рабочая точка — пересечение характеристики насоса с характеристикой сети.
7. **РЧВ**: «только АУП» или «суммарно с ВПВ»; наружное пожаротушение — ручной ввод; сравнение с размерами пользователя (полезный объём × 0,95).
8. **Проверки**: размещение, скорости (≤ 10 м/с напорные), уклоны, секции, запас оросителей, приложение В. Результат — список замечаний с узлом/участком и пунктом нормы.

## 7. Гидравлика
### 7.1 Модель
- Ороситель — эмиттер: q = 10·K·√P (P в МПа, K в л/(с·МПа^0,5)).
- Потери на участке: ΔP = Q²·L / (100·Kт) · (1 + k_м), k_м = 0,20 по умолчанию (Б.1.3.13); при заполненной вкладке данных производителя — эквивалентные длины или ξ вместо 20 %.
- Геодезика: Z = H/100 МПа.
- Б.1 считать как P = (q/10K)² (в тексте 2020 г. опечатка). Закреплено тестом.

### 7.2 Солвер
- Метод глобального градиента (Todini–Pilati, как в EPANET) с эмиттерами. Разреженная система, итерации Ньютона.
- Сходимость: изменение расходов < 1e-6 л/с и невязка по узлам < 1e-6; не сошлось за N итераций → замечание, а не исключение.
- Для тупиковых сетей результат должен совпадать с последовательным расчётом приложения Б (формулы Б.9–Б.22) — это отдельный тест.
- Нормативный вариант для колец: 50 % на полукольцо, 100 % при нормально закрытых разделительных задвижках (Б.1.2.16.1, Изм. № 1). В записку и подбор насоса идёт более тяжёлый результат из двух.

### 7.3 Диктующая зона
- Кандидаты: зоны площадью ≥ S, которые сдвигаются по сетке оросителей с шагом одного оросителя по всем секциям.
- Для каждого кандидата открыты только оросители зоны, решается сеть, считается требуемое P_н на насосе.
- Диктующая — с максимальным P_н (при равенстве — с большим Q_с). В журнал пишутся 3 лучших кандидата с причиной выбора.
- Форма зоны (соотношение сторон) — открытый вопрос, согласовать со специалистом; параметр в настройках.

### 7.4 Независимая проверка
Экспорт сети в EPANET (.inp, эмиттеры с показателем 0,5). Формулы потерь в EPANET другие, поэтому сравнение идёт с допуском, а не до знака.

## 8. Импорт DWG/DXF (соглашение о слоях)
Чертёж готовит проектировщик по шаблону `data/templates/WaterAuto_layers.dwg`. Единицы — мм.

| Слой | Объект | Что читается |
|---|---|---|
| `ПТ_КОНТУР` | замкнутая полилиния | контур помещения или зоны; имя помещения — текст внутри контура |
| `ПТ_КОЛОННЫ` | замкнутая полилиния или блок | сечение колонны |
| `ПТ_БАЛКИ` | замкнутая полилиния | **Толщина (Thickness) = высота балки, мм**; Уровень (Elevation) — отметка низа перекрытия |
| `ПТ_КОРОБА` | замкнутая полилиния | ширина из геометрии; Уровень = отметка низа короба |
| `ПТ_ОТМЕТКИ` | текст (TextEntity/MText) | высотная отметка в метрах («-1,200», «±0,000», «отм. +3,600»); используется для предложений отметок пола этажа и насосной в проверке чертежа |
| `ПТ_ЗАПРЕТ` | замкнутая полилиния | зона без оросителей |
| `ПТ_ВВОД` | точка или блок | подключение (стояк, узел управления) |

Проверки при импорте (ошибка с координатами, импорт не продолжается): незамкнутый контур; колонна или балка вне контура; балка с толщиной 0; пересекающиеся контуры; нет `ПТ_ВВОД`. Нечисловой текст на слое `ПТ_ОТМЕТКИ` — предупреждение, импорт продолжается.

Выход в тех же координатах (DXF): `ПТ_ОРОСИТЕЛИ`, `ПТ_ТРУБЫ` (DN в свойствах), `ПТ_УЧАСТКИ` (номера участков расчёта), `ПТ_ДИКТ_ЗОНА`, `ПТ_ЗАМЕЧАНИЯ`. Плагин AutoCAD позже читает и пишет те же слои напрямую.

## 9. Нормы как данные
Пример записи (документ и редакция — на уровне файла, формат полностью — README §6.1):
```json
{
  "id": "sp485.t6_1.group2",
  "clause": "табл. 6.1",
  "values": { "i_water": 0.12, "i_foam": 0.08, "Q_water": 30, "Q_foam": 20, "S": 120, "t_min": 60, "maxSpacing": 3.5 },
  "units": { "i_water": "л/(с·м²)", "i_foam": "л/(с·м²)", "Q_water": "л/с", "Q_foam": "л/с", "S": "м²", "t_min": "мин", "maxSpacing": "м" },
  "attrs": { "group": "2" }
}
```
- Файлы норм проверяются JSON-схемой `data/schemas/norms.schema.json` (в CI — `tools/ValidateData`).
- Редакция в данных: СП 485 с изм. № 1 (введено с 01.01.2026) и № 2 (введено с 09.07.2026; приказ от 26.05.2026).
- ВПВ для объектов в КР — СН КР 40-04:2025, разд. 7 и прил. Ж (`data/norms/snkr40_04`, ADR 0010). Совмещение с АУП — по Б.1.3.7, Б.1.3.8, Б.1.3.15, Б.1.3.16 СП 485.
- Единицы Kт (л²/с²) и A (с²/л²) записаны так, как в тексте СП; их согласованность с формулами Б.6 — открытый вопрос TASK-0001.
- В проект записывается снимок норм; старый проект пересчитывается по своей редакции, новый — по актуальной. Разница редакций показывается пользователю.

### 9.1 Профиль заказчика
Требования конкретного заказчика, которые строже норм или задают практику (например, шаг оросителей ≤ 3 м у Фонда реновации, грувлочные соединения, правила жокей-насоса), хранятся отдельно в `data/profiles/*.json` в том же формате, что нормы (значение, источник, страница). Порядок применения: СП 485 → профиль может только ужесточить. В записке и CalcLog у каждой величины видно, из нормы она или из профиля. Профиль, который ослабляет норму, отклоняется при загрузке. Формат — `data/schemas/profile.schema.json`: у записи страница документа заказчика, вид (`requirement`, `recommendation`, `practice`, `info`) и, если ужесточает норму, ссылка `tightens` на id записи нормы; `tools/ValidateData` проверяет, что значение профиля не слабее нормы. Первый профиль — `data/profiles/fond-renovacii-2019.json`.

### 9.2 Уточнения по сверке с ГидРаВПТ
- Kт: строка табл. Б.2, если есть; иначе формула Б.8 по внутреннему диаметру. Источник значения — в CalcLog.
- Узел управления (Б.32): P_уу = ξ·γ·Q², Q в м³/ч, γ = 9,80665, P_уу в МПа; ξ из паспорта.
- Пожарные краны на питающих трубах — эмиттеры с расходом при фактическом давлении; отдельно проверка Q ≥ нормы СП 10.13130.
- Разбор и открытые вопросы — `docs/gidravpt_reports_analysis.md`.

## 11. Тесты
- Модульные тесты формул (Б.1, Б.4–Б.30, перевод K).
- Эталоны-гейты: `Volkov2020-Ex1`, `Meshman2002-P9-v1/-v2` (`active`) и `GidRaVPT-R2-plain` (`compat`).
- ИОС2.2 — `compat`, не гейт (В-10): q и ΔP распределительной сети сверяются с точностью округления проекта; подача 168,84 м³/ч расчётная, точка насоса 184,80 м³/ч / 34,90 м — по кривой; известные ошибки проекта помечены как ошибки источника.
- Тупиковая сеть: солвер = последовательный расчёт приложения Б.
- Эталоны GidRaVPT-R2 (`pending` до выяснения множителя 1/0,95²) и GidRaVPT-R2-plain (`compat`) — совместимость с сертифицированной программой; R1 — когда будет отчёт. Эталоны из пособий: Meshman2002-P9-v1/-v2, Volkov2020-Ex1 (`tests/Golden/README.md`).
- Сравнение с EPANET на наборе сетей (допуск определить).
- Импорт: набор DXF с намеренными ошибками.
- Выпадающие списки ввода: `InputCatalog` (Application) возвращает группы табл. 6.1, оросители каталога, стандарты труб, DN, установки насосной и строки табл. Ж.1 — тест проверяет, что значения и подписи берутся из `data/`, а не дублируются в коде.
- Проверка чертежа: `DrawingPreview` на сгенерированных DXF проверяется на распознавание помещений/насосной/вводов и предложения по геометрии (высота помещения, отметка труб, H, длина подводящего); `PumpAdvisor` — порядок кандидатов совпадает с автоподбором расчёта, габариты/ось коллектора совпадают с каталогом. `PipelineResult.PumpRoom` (помещение насосной и габариты установки) проверяется в сквозном тесте насосной.
- Импорт высотных отметок: слой `ПТ_ОТМЕТКИ` — форматы «-1,200»/«±0,000»/«отм. +3,600»/точка, зеркальные тексты, нечисловой текст — предупреждение без остановки импорта; `DrawingPreview` предлагает отметки пола этажа/насосной и пересчитывает от них высоты и H.
- Жокей-насос: `design.jockey` — только решение проектировщика (пусто = не задано); проверки `jockey.manual`/`jockey.flow`/`jockey.settings` и абзац в записке прямо указывают, что норма расход и уставки не задаёт (В-07).
- Предпросмотр выпуска: `XlsxPreview`/`DocxPreview` читают спецификацию и записку без внешних приложений (`OutputPreview` в Application), `PreviewWindow` показывает данные; тесты не зависят от вёрстки, проверяют непустые строки и ключевые слова.
- Быстрый проект: `QuickProject.Create` проверяется консольным прогоном (создание файла, оценки по чертежу, повторный вызов не перезаписывает проект) — окно `QuickProjectWindow` не пишет файлы и только возвращает запрос.
- Тест архитектуры: Calc не ссылается на Import/Export/Reports/App.
- Допуск сходимости с эталоном — открытый вопрос (концепция, раздел 9).

## 13. Этапы
0. Скелет решения, CI, тест архитектуры, JSON-схема норм, табл. 6.1 и Б.1–Б.2 в данных.
1. Гидравлика тупиковой сети + эталоны-гейты из пособий и ГидРаВПТ проходят; ИОС2.2 — `compat`.
2. Импорт DWG/DXF по слоям + раскладка для прямоугольного и сложного контура с колоннами и балками; подбор шага X × Y по зонам (сравнение X × Y и Y × X по числу оросителей).
3. Сквозной срез Маликова 91: импорт → раскладка → расчёт → записка docx + спецификация xlsx/pdf + DXF.
4. Солвер колец, нормативный вариант 50/100 %, поиск диктующей зоны, проверка через EPANET.
5. Насос по характеристике, РЧВ в двух режимах.
6. Приложение В (после независимой проверки одного примера).
7. UI: схема с замечаниями. Анимация потоков, дренчерные завесы, плагины CAD — после v1.
